# PaymentsCloud

Telegram-бот для приёма заявок на пополнение Steam. Пользователь указывает сумму и логин, оплачивает перевод через ЮMoney и проверяет его статус. Администратор получает оплаченный заказ и принимает его в работу. Само пополнение Steam выполняется вручную.

Проект в разработке. Это исходники для продолжения работы, без подключённых аккаунтов и рабочих данных.

## Возможности

- Заявки на 100–14 999 рублей с расчётом комиссии.
- Оплата банковской картой через ЮMoney, проверка метки, суммы, направления и статуса перевода.
- Сохранение пользователей и заявок в PostgreSQL, защита от повторного подтверждения.
- Админская статистика и принятие заказа одним исполнителем.
- Поддержка, ограничение частоты запросов и блокировка пользователей через Redis.

## Запуск

Нужны Python 3.14, [uv](https://docs.astral.sh/uv/), PostgreSQL, Redis и публичный HTTPS-адрес для Telegram webhook. Версии Python и зависимостей закреплены в `.python-version` и `uv.lock`.

```bash
uv sync --frozen
uv run --frozen python init_env.py
```

Заполните созданный `.env` в редакторе. Скрипт генерирует webhook-secret, устанавливает права `0600` и сохраняет существующий файл при повторном запуске. Остальные значения выдаются внешними сервисами.

| Переменная | Назначение |
| --- | --- |
| `TOKEN` | Токен Telegram-бота |
| `PG_DSN` | PostgreSQL DSN отдельной базы проекта |
| `REDIS_URL` | Адрес отдельной базы Redis |
| `WEBHOOK_SECRET` | Секрет проверки Telegram webhook |
| `BASE_WEBHOOK_URL` | Публичный HTTPS origin без пути |
| `YOOMONEY_TOKEN` | Токен кошелька с правом `operation-history` |
| `YOOMONEY_RECEIVER` | Номер кошелька для входящих переводов |
| `SUPPORT_URL` | HTTPS-ссылка на поддержку |

Все параметры обязательны. Для удалённых PostgreSQL и Redis используйте TLS с проверкой сертификатов. Не помещайте секреты в команды и историю терминала.

```bash
uv run --frozen --env-file .env python main.py
```

Приложение слушает `127.0.0.1:8083`. Обратный прокси должен передавать HTTPS-запросы с пути `/webhook` на этот адрес. При старте создаются отсутствующие таблицы, проверяется Redis и регистрируется webhook. Существующие таблицы и заявки сохраняются.

После первого `/start` назначьте первого администратора в доверенном SQL-клиенте, указав его Telegram ID параметром запроса:

```sql
UPDATE public.paymentscloud_users SET admin = TRUE WHERE user_id = :user_id;
```

## Проверки

```bash
uv run --frozen python check.py
uv run --frozen pip-audit
gitleaks git --redact
```

Первая команда проверяет форматирование, статический анализ и регрессионные тесты с предупреждениями как ошибками. Тесты изолированы от Telegram, ЮMoney и рабочих баз.

Для отдельной проверки конкурентного подтверждения и сохранения данных запустите чистую локальную PostgreSQL с базой `paymentscloud_test`. Сохраните её DSN в `PAYMENTSCLOUD_TEST_DSN` внутри отдельного `.env.integration`, затем выполните:

```bash
uv run --frozen --env-file .env.integration python -m pytest -W error tests/integration_db.py
```

Этот тест изменяет только выделенную базу и принимает только `localhost` или `127.0.0.1`. Рабочий DSN использовать нельзя.

## Текущее состояние

Локально проверены конфигурация, денежные расчёты, доступ к чужим платежам, админские действия, повторное подтверждение и проверка ответа платёжного сервиса. На изолированной PostgreSQL 16 проверены конкуренция, идемпотентность, переходы статусов и сохранение записей при повторной инициализации. Настоящие переводы, webhook и подключение Redis остаются непроверенными.

До приёма реальных оплат нужны восстановление доставки уведомлений после сбоя и сверка незавершённых переводов. Сейчас заявка, оплаченная после локальной отмены, разбирается через поддержку; сбой после записи успешного статуса может оставить администратора без уведомления. Форма ввода хранится в памяти и сбрасывается при перезапуске. Автоматического пополнения Steam и возвратов нет.

Расчёт карточной комиссии основан на [документации ЮMoney](https://yoomoney.ru/docs/payment-buttons/using-api/forms). Фактическое подключение и тарифы нужно сверить перед использованием. В репозитории нет рабочих токенов, кошельков, базы пользователей и дампов.
